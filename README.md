# 글 사이트

> **저작권**: 이 저장소의 글과 사이트 자체의 저작권은 글쓴이 Complex 에게 있습니다. 글은 출처를 밝히면 퍼갈 수 있지만 상업적 이용과 내용 변경은 안 되고, 사이트의 틀과 코드는 허락 없이 가져다 쓸 수 없습니다. 자세한 내용은 [LICENSE](LICENSE) 에 있습니다.

GitHub Pages 가 자동으로 만들어 주는 글 사이트입니다. 글 파일을 올리면 1~2분 뒤 사이트에 반영됩니다.

## 화면

- 왼쪽: 항목 나무. Section 아래에 소주제가 접혀 있고, 화살표를 누르면 펼쳐집니다.
- 오른쪽: 왼쪽에서 항목을 고르면 그 항목(하위 소주제 포함)에 든 글의 제목·요약·날짜가 나옵니다. 요약을 누르면 글이 열립니다.
- 좁은 화면(휴대폰)에서는 항목 나무가 위로 올라가고 `항목` 단추로 여닫습니다.

- 글 끝: `링크 복사` 단추가 있고, 공유 창을 지원하는 기기(주로 휴대폰)에서는 `공유` 단추도 나옵니다.
- 본문을 50자 넘게 복사해 가면 끝에 출처(글 제목, 사이트 이름, 주소)가 자동으로 붙습니다. 코드만 복사할 때와, 쓰기를 켠 본인 브라우저에서는 붙지 않습니다. 기준 글자 수는 `assets/js/site.js` 의 `QUOTE_MIN` 입니다.

## 구조

```
_writing/
  수필/                     ← Section
    first-essay.md          ← 글
  기술/                     ← Section
    음성인식/               ← 소주제 (폴더)
      Zipformer/            ← 소주제 아래 소주제
        lr-notes.md
sections/
  수필.md  기술.md  정보.md  ← Section 마다 하나: 이름·설명·메뉴 순서
_items/                     ← (있을 때만) 아직 글이 없는 소주제의 이름표
_data/names/                ← (있을 때만) 항목의 보이는 이름·설명을 바꾼 기록
_data/about/                ← 소개 글 (고칠 때마다 하나씩 쌓이고 나중 것이 보임)
_data/site/                 ← (있을 때만) 첫 화면 소개 문장을 바꾼 기록
_data/moves/                ← (있을 때만) 글을 다른 항목으로 옮긴 기록
_data/order/                ← (있을 때만) 항목 순서를 바꾼 기록
_data/itemmoves/            ← (있을 때만) 항목을 다른 항목 아래로 옮긴 기록
```

- `_writing/` 의 첫 단계 폴더가 Section, 그 아래 폴더가 소주제입니다. 깊이 제한은 없습니다.
- 폴더 이름이 그대로 소주제 이름으로 보입니다 (보이는 이름만 따로 바꿀 수도 있습니다). 파일 이름은 글 주소에만 쓰이고, 화면에는 머리말의 `title` 이 나옵니다.
- **주소**
  - 글: `/p/파일이름/` (예: `/p/k3x9q2/`). 파일 이름은 자동으로 만든 짧은 코드이고, 항목과는 상관없습니다. 그래서 글을 옮기거나 항목 이름을 바꿔도 **글 주소는 바뀌지 않습니다.** 댓글도 이 이름에 묶여 있습니다. 같은 파일 이름을 다른 폴더에 또 쓰면 주소가 겹치므로 쓰면 안 됩니다.
  - 항목: **지금 보이는 이름을 따라갑니다.** Section 은 `/이름/`, 소주제는 `/Section이름/#소주제이름` 꼴이고, 이름을 바꾸거나 항목을 옮기면 주소도 함께 바뀝니다 (예전 항목 주소는 더 열리지 않습니다).
- 글이 하나도 없는 폴더는 나무에 나오지 않습니다. 빈 항목을 먼저 보이게 하려면 아래 '항목 만들기' 를 보세요.

## 글 올리기

1. 새 글 파일 만들기 (없는 소주제 폴더는 함께 만들어집니다)

   ```bash
   ./new.sh 수필 "가을 산책"
   ./new.sh 기술/음성인식 "Zipformer 학습률 정리"
   ```

2. 생긴 파일을 열어 머리말(`---` 사이) 아래에 글을 씁니다. 문단은 빈 줄로 나눕니다.

   ```
   ---
   title: 가을 산책
   date: 2026-09-30
   summary: 목록에 보일 한두 문장 (비워 두면 글의 첫 문단이 요약이 됩니다)
   ---

   여기부터 글.
   ```

3. 올리기

   ```bash
   git add -A
   git commit -m "가을 산책"
   git push
   ```

터미널 없이도 됩니다. 아래 '브라우저에서 쓰기' 를 보세요. 브라우저에서는 쓰는 글이 자동으로 임시저장됩니다.

## GitHub 연결 (그림 넣기, 바로 저장)

글 쓰기 화면(`/write/`) 맨 위의 `GitHub 연결` 에서 이 저장소의 토큰을 한 번 넣어 두면:

- 본문 칸에 그림을 **붙여 넣거나(Ctrl+V) 끌어다 놓으면** 그 그림이 저장소의 `assets/img/` 에 올라가고 커서 자리에 들어갑니다. 큰 사진은 긴 변 1600 으로 줄여서 올립니다.
- 게시·고치기·지우기·옮기기·이름 바꾸기·순서 바꾸기가 GitHub 화면을 거치지 않고 **누르는 즉시 저장**됩니다.
- 저장하면 화면 아래에 "사이트에 반영하는 중"이라는 알림이 뜨고, GitHub 가 사이트를 다 만들면(보통 1분쯤) 화면이 알아서 새로 고쳐집니다. 글을 쓰는 중이거나 양식을 열어 둔 때에는 새로 고치지 않고 `새로 고침` 단추만 보여 줍니다.
- 반영된 뒤 10분 동안은 다른 쪽으로 옮겨 가도 브라우저가 기억해 둔 옛 화면 대신 새 화면을 받아 옵니다.
- `?write=on` 을 하지 않아도 그 브라우저는 글쓴이로 봅니다.

연결하는 법: `토큰 만들기 화면 열기` → Repository access 에서 **Only select repositories** 를 고르고 이 저장소 선택 → Generate token → 나온 값을 칸에 붙여 넣고 `연결하기`. 권한(Contents: Read and write)과 기한(1년)은 미리 채워져 열립니다.

- 토큰은 그 브라우저에만 저장됩니다. 브라우저마다 한 번씩 연결하고, 남과 같이 쓰는 컴퓨터에서는 연결하지 않습니다.
- 끊으려면 글 쓰기 화면의 `연결 끊기`. 토큰 자체를 없애려면 GitHub 의 Settings → Developer settings → Personal access tokens 에서 지웁니다.
- 기한이 지나면 "토큰이 만료됐다"는 안내가 나옵니다. 같은 방법으로 다시 연결합니다.
- 연결하지 않아도 지금까지의 방식(GitHub 화면에서 Commit changes)으로 쓸 수 있습니다. 그림 넣기만 연결이 필요합니다.
- 바로 저장되는 커밋에는 필명(`_config.yml` 의 `author`)과 GitHub 의 비공개용 메일 주소가 적힙니다.
- 글 쓰기 화면의 `미리보기` 는 본문이 사이트에 나올 모습을 대략 보여 줍니다. 방금 올린 그림도 보입니다.

## 댓글

글 아래에 댓글 칸이 있습니다. 누구나 이름(비우면 익명)과 내용만 적으면 쓸 수 있고, 쓰는 즉시 보입니다. 가입도 승인도 없습니다.

- **자기 댓글 고치기·지우기**: 댓글을 쓴 그 브라우저에서는 자기 댓글 아래에 `고치기`·`지우기` 가 보입니다. (처음 댓글을 쓸 때 그 브라우저에 이름 없는 계정이 하나 만들어지고, 그 계정으로 쓴 댓글만 바꿀 수 있습니다. 다른 기기나 방문 기록을 지운 브라우저에서는 바꿀 수 없습니다.)
- **비밀번호로 고치기·지우기**: 댓글을 쓸 때 비밀번호(선택, 4자 이상)를 적어 두면 다른 기기·다른 브라우저에서도 그 댓글의 `고치기`·`지우기` 를 누르고 비밀번호를 넣어 바꿀 수 있습니다. 비밀번호는 그대로 보내거나 저장하지 않고 바꾼 값만 저장하며, 그 값은 아무도 읽을 수 없는 자리에 들어갑니다. 비밀번호는 나중에 바꾸거나 찾을 수 없습니다.
- **글쓴이의 댓글 관리**: 글 쓰기 화면의 `댓글 관리` 에서 로그인하면 그 브라우저에서는 모든 댓글에 `지우기` 가 보이고, 글쓴이가 쓴 댓글에는 `글쓴이` 표시가 붙습니다.
- 댓글은 사이트 파일이 아니라 Firebase(Google 의 무료 저장 서비스)에 들어갑니다. `_config.yml` 의 `comments_project` 에 Firebase 프로젝트 ID 를 적으면 켜지고, 비우면 댓글 칸이 나오지 않습니다.
- Firebase 쪽 준비
  1. 프로젝트 만들기 → Firestore Database 만들기
  2. Authentication → 로그인 방법에서 **익명** 과 **이메일/비밀번호** 를 켭니다
  3. Authentication → 사용자 → 사용자 추가로 글쓴이 계정(이메일·비밀번호)을 하나 만듭니다. 목록에 나오는 **사용자 UID** 를 `_config.yml` 의 `comments_owner_uid` 에 적습니다
  4. 프로젝트 설정(톱니바퀴) → 일반 의 **웹 API 키** 를 `_config.yml` 의 `comments_api_key` 에 적습니다 (공개해도 되는 값입니다. 비밀번호는 어디에도 적지 않습니다)
  5. Firestore Database → 규칙에 아래를 붙여 넣고 `글쓴이_UID` 를 3번의 사용자 UID 로 바꾼 뒤 게시

  ```
  rules_version = '2';
  service cloud.firestore {
    match /databases/{database}/documents {
      match /pages/{page}/comments/{comment} {
        function ok(d) {
          return d.name is string && d.name.size() <= 30
              && d.text is string && d.text.size() > 0 && d.text.size() <= 2000;
        }
        // 비밀번호를 맞혀 이 댓글을 쓴 사람으로 확인된 브라우저인가
        function claimed() {
          return exists(/databases/$(database)/documents/pages/$(page)/comments/$(comment)/claims/$(request.auth.uid));
        }
        function writer() {
          return request.auth.uid == resource.data.get('uid', '') || claimed();
        }

        allow read: if true;
        allow create: if ok(request.resource.data)
                      && (request.resource.data.keys().hasOnly(['name', 'text'])
                          || (request.auth != null
                              && request.resource.data.keys().hasOnly(['name', 'text', 'uid', 'pw'])
                              && request.resource.data.uid == request.auth.uid
                              && (!('pw' in request.resource.data)
                                  || (request.resource.data.pw == true
                                      && existsAfter(/databases/$(database)/documents/pages/$(page)/comments/$(comment)/secret/key)))));
        allow update: if request.auth != null && writer()
                      && request.resource.data.keys().hasOnly(['name', 'text', 'uid', 'pw', 'edited'])
                      && request.resource.data.uid == resource.data.uid
                      && request.resource.data.name == resource.data.name
                      && request.resource.data.get('pw', false) == resource.data.get('pw', false)
                      && request.resource.data.edited == true
                      && ok(request.resource.data);
        allow delete: if request.auth != null
                      && (request.auth.uid == '글쓴이_UID' || writer());

        // 댓글 비밀번호를 한 번 더 섞어 바꾼 값. 아무도 읽을 수 없다
        match /secret/{doc} {
          allow read: if false;
          allow create: if doc == 'key' && request.auth != null
                        && getAfter(/databases/$(database)/documents/pages/$(page)/comments/$(comment)).data.uid == request.auth.uid
                        && request.resource.data.keys().hasOnly(['hash'])
                        && request.resource.data.hash is string
                        && request.resource.data.hash.size() == 64;
        }
        // 비밀번호를 맞힌 브라우저의 기록. 맞는 비밀번호일 때만 만들어진다
        match /claims/{uid} {
          allow read: if false;
          allow create: if request.auth != null && request.auth.uid == uid
                        && request.resource.data.keys().hasOnly(['k'])
                        && request.resource.data.k is string
                        && request.resource.data.k.size() == 64
                        && hashing.sha256(request.resource.data.k).toHexString().lower()
                           == get(/databases/$(database)/documents/pages/$(page)/comments/$(comment)/secret/key).data.hash;
        }
      }
    }
  }
  ```

- 규칙의 뜻: 누구나 읽고 쓸 수 있습니다(이름 30자·내용 2000자까지). 댓글에 적히는 계정 번호는 쓴 사람 자신의 것만 됩니다. 고치기는 쓴 사람과 비밀번호를 맞힌 사람만(내용만), 지우기는 거기에 글쓴이까지 됩니다. 비밀번호를 바꾼 값(`secret`)과 맞힌 기록(`claims`)은 아무도 읽을 수 없습니다.
- 댓글을 지워도 그 댓글의 `secret`·`claims` 기록은 Firebase 에 남습니다(아주 작고, 보이지 않습니다).
- `comments_api_key` 를 비워 두면 고치기·지우기 없이 쓰기만 됩니다. 그때 지우려면 Firebase 콘솔 → Firestore Database → `pages` 아래에서 찾아 지웁니다. (`pages` 바로 아래 이름은 글 파일 경로를 글자로 바꾼 것입니다.)
- 댓글에는 글자만 들어갑니다. 꾸밈이나 링크 태그를 적어도 글자 그대로 보입니다.

## 브라우저에서 쓰기

사이트 주소 끝에 `?write=on` 을 붙여 한 번 들어가면(예: `https://aiverything.github.io/?write=on`) **그 브라우저에서만** 아래 링크가 보입니다.

| 링크 | 어디에 | 하는 일 |
|---|---|---|
| 이 항목에 글 쓰기 | 항목을 고른 화면, 글 화면 | 사이트의 글 쓰기 화면이 그 항목으로 열립니다 |
| 글 쓰기 | 왼쪽 아래 | 글 쓰기 화면. 임시저장 글이 있으면 그 수가 옆에 나옵니다 |
| 이 글 고치기 | 글 화면 | 사이트의 글 쓰기 화면이 그 글이 채워진 채 열립니다. 고쳐서 `저장하기` |
| 소개 글 고치기 | 소개 쪽 | 사이트의 편집 화면이 지금 소개 글이 채워진 채 열립니다. 고쳐서 `저장하기` |
| 소개 문장 고치기 | 첫 화면 | 첫 화면 맨 위의 문장을 그 자리에서 고칩니다 |
| 이 항목 설명 고치기 | 항목을 고른 화면 | 항목 제목 아래에 나오는 설명을 고칩니다. 비워서 보내면 설명이 없어집니다 |
| 사이트 이름·필명 고치기 | 첫 화면 | `_config.yml` 이 GitHub 편집 화면으로 열립니다. 맨 위 두 줄(`title`, `author`)을 고칩니다 |

소개 글·소개 문장·항목 설명은 고칠 때마다 새 기록 파일이 하나 생기는 방식입니다(파일을 직접 고칠 필요가 없게 하려는 것). 기록은 각각 `_data/about/`, `_data/site/`, `_data/names/` 에 쌓이고 가장 나중 것이 보입니다.
| 이 글 지우기 | 글 화면 | GitHub 의 삭제 화면이 열립니다. Commit changes 를 누르면 지워집니다 |
| 쓰기 링크 끄기 | 왼쪽 아래 | 이 브라우저에서 링크를 다시 감춥니다 (`?write=off` 와 같음) |

### 글 쓰기와 임시저장

- 글 쓰기 화면에서 쓰는 글은 **쓰는 대로 자동으로 임시저장**됩니다. 임시저장 글은 그 브라우저 안에만 있고 사이트에도 GitHub 에도 올라가지 않습니다. 그래서 다른 사람은 볼 수 없고, 다른 기기에서도 보이지 않습니다.
- 브라우저의 사이트 데이터(방문 기록)를 지우면 임시저장 글도 지워집니다. 오래 두고 쓸 긴 글은 따로 보관해 두세요.
- 다 쓴 글은 `게시하기` 를 누릅니다. 짧은 글은 GitHub 의 새 파일 화면이 내용이 채워진 채 열리고, 긴 글은 글이 복사된 뒤 빈 화면이 열리므로 본문 칸에 붙여 넣습니다(Ctrl+V). Commit changes 를 누르면 1~2분 뒤 게시됩니다.
- 게시한 뒤에도 임시저장 글은 남아 있습니다. `이 임시저장 글 지우기` 로 지웁니다.
- **올린 글 고치기**: 글 화면의 `이 글 고치기` 를 누르면 올라가 있는 글을 불러와 제목·요약·본문 칸에 채웁니다. 고치는 중에도 자동으로 임시저장됩니다. `저장하기` 를 누르면 고친 글이 복사되고 GitHub 의 편집 화면이 열립니다. 본문 칸을 한 번 누르고 **전체 선택(Ctrl+A) → 붙여넣기(Ctrl+V)** 로 통째로 바꾼 뒤 Commit changes 를 누릅니다. (이미 있는 파일은 GitHub 화면을 채워서 열 수 없어서 이 한 단계가 더 있습니다.)
- 고칠 때는 항목과 글 주소가 바뀌지 않습니다. 다른 항목으로 보내려면 '글 옮기기' 를 씁니다.
- `주소에 쓸 이름` 은 글 주소의 끝부분입니다(`/p/이름/`). 자동으로 만든 짧은 코드가 들어 있고, 원하는 이름으로 고쳐도 됩니다. 이미 다른 글이 쓰는 이름이면 알려 줍니다. 글을 올린 뒤에는 바뀌지 않습니다.
- 브라우저마다 따로 켜야 합니다 (휴대폰과 PC 각각). 방문 기록을 지우면 다시 켜야 합니다.
- 이것은 링크를 감추는 것일 뿐입니다. 저장은 GitHub 에 로그인한 본인(과 공동 작업자로 추가한 계정)만 할 수 있습니다.

공개 저장소이므로 글 파일 자체는 누구나 볼 수 있습니다. `published: false` 로 숨긴 글도 저장소에서는 보이고, 고치거나 지운 내용도 변경 기록에 남습니다.

## 항목 만들기

글을 쓰면서 새 폴더에 넣으면 그 폴더가 곧 새 소주제가 됩니다. 글 없이 항목부터 만들어 두려면:

| 어디서 | 새 Section | 새 소주제 |
|---|---|---|
| 브라우저 (쓰기를 켠 상태) | 왼쪽 아래 `새 Section 만들기` | 위 항목을 고른 뒤 `이 항목 아래에 새 항목 만들기` |
| 터미널 | `./new-item.sh 여행 "여행하며 적은 글"` | `./new-item.sh 기술/음성인식/Zipformer` |

브라우저에서는 이름을 적고 `GitHub 에서 만들기` 를 누르면 GitHub 의 새 파일 화면이 채워진 채 열립니다. 거기서 Commit changes 만 누르면 됩니다.

- Section 은 `sections/이름.md` 파일입니다 (이름·설명·메뉴 순서). 이 파일 이름이 Section 쪽의 주소(`/이름/`)가 됩니다. 글은 `_writing/폴더이름/` 에 들어가고, 폴더 이름은 그 파일의 `folder` 값(없으면 파일 이름)입니다. 사이트에서 Section 이름을 바꾸면 파일 이름은 새 이름으로 바뀌고 `folder` 에 원래 폴더 이름이 남습니다.
- 글이 없는 소주제는 `_items/기술/음성인식/Zipformer.md` 같은 이름표 파일(내용은 `---` 두 줄)로 나무에 보입니다. 그 항목에 글이 생긴 뒤에는 이름표를 지워도 됩니다.
- 폴더 이름을 바꿀 때는 `_items/` 의 이름표도 같이 바꿉니다.

### 항목 지우기

- 브라우저 (쓰기를 켠 상태): 항목을 고른 뒤 `이 항목 지우기` → `GitHub 에서 지우기` → Commit changes.
- **글도 아래 항목도 없는 빈 항목만** 지울 수 있습니다. 글이 있으면 먼저 옮기거나 지우고, 아래 항목이 있으면 아래 항목부터 지웁니다. (글이 함께 사라지는 일이 없게 하려는 것입니다.)
- 글만으로 생긴 소주제(이름표가 없는 것)는 들어 있던 글이 없어지면 저절로 사라집니다.
- 터미널에서는 해당 파일을 지웁니다: Section 은 `sections/이름.md`, 빈 소주제는 `_items/…/이름.md`.

## 항목 이름 바꾸기

| 어디서 | 방법 |
|---|---|
| 브라우저 (쓰기를 켠 상태) | 항목을 고른 뒤 `이 항목 이름 바꾸기` → 이름을 적고 `GitHub 에서 바꾸기` → Commit changes |
| 터미널 | `./rename-item.sh 기술/음성인식 "음성 인식 (ASR)"` (앞은 폴더 이름, 뒤는 바꿀 이름) |

- **이름과 함께 그 항목의 주소도 바뀝니다.** 소주제는 주소의 `#` 뒤가, Section 은 `/이름/` 이 새 이름으로 바뀝니다. 저장한 내용이 반영되면 화면이 새 주소로 알아서 넘어갑니다.
- **글 주소와 폴더 이름은 그대로입니다.** 글 주소(`/p/…/`)에는 항목 이름이 들어 있지 않아서, 이미 퍼진 글 링크와 댓글이 끊기지 않습니다.
- Section 의 주소까지 바뀌는 것은 GitHub 에 연결한 브라우저에서 바꿀 때입니다 (이름 기록과 `sections/` 파일 이름 바꾸기를 한 번에 저장합니다). 연결 없이 바꾸거나 터미널의 `rename-item.sh` 로 바꾸면 Section 은 보이는 이름만 바뀝니다. 그때는 `git mv "sections/옛이름.md" "sections/새이름.md"` 를 하고 그 파일에 `folder: 원래폴더이름` 한 줄을 넣으면 주소도 바뀝니다.
- 바꾼 기록은 `_data/names/` 에 파일로 쌓이고(`path`, `name` 두 줄), 같은 항목은 나중 기록이 이깁니다. 원래 이름으로 돌리려면 그 항목의 기록 파일을 지웁니다.
- 글을 쓰거나 옮길 때의 폴더 이름은 원래 이름입니다. 브라우저의 `이 항목에 글 쓰기` 는 알아서 맞는 폴더로 갑니다.
- 이름을 바꿔도 나무에서의 자리는 그대로입니다. 자리는 위 '항목 순서 바꾸기' 로 바꿉니다.
- 폴더 이름까지 바꾸려면 터미널에서 `git mv "_writing/기술/옛이름" "_writing/기술/새이름"` 으로 폴더를 옮깁니다. 글 주소는 바뀌지 않지만, 그 폴더 경로로 적힌 이름·순서·옮긴 기록(`_data/`)은 따라오지 않으므로 권하지 않습니다.

## 항목 순서 바꾸기

- 브라우저, PC (쓰기를 켠 상태): 왼쪽 나무에서 항목을 위아래로 끌어다 놓습니다. 놓일 자리에 붉은 줄이 보입니다. 확인 줄의 `GitHub 에서 바꾸기` → Commit changes.
- 순서는 같은 단계 안에서 바뀝니다 (Section 끼리, 또는 같은 항목 아래의 소주제끼리). 놓을 항목의 **위쪽·아래쪽 가장자리**에 놓으면 순서 바꾸기입니다.
- 놓으면 나무에 미리 반영되어 보이고, `취소` 를 누르면 원래 순서로 돌아갑니다. Commit 을 해야 사이트에 남습니다.
- 바꾼 순서는 `_data/order/` 에 파일로 쌓이고(`parent` 와 `items` 목록), 같은 단계는 나중 기록이 이깁니다. 기록에 없는 새 항목은 뒤에 붙습니다.
- 기록이 없을 때의 순서: Section 은 `sections/이름.md` 의 `order`, 소주제는 폴더 이름순.
- 휴대폰에서는 끌기가 되지 않습니다.

## 항목을 다른 항목 아래로 옮기기

- 브라우저, PC (쓰기를 켠 상태): 왼쪽 나무에서 항목을 끌어 다른 항목의 **가운데**에 놓습니다. 놓일 항목에 테두리가 생깁니다. 확인 줄의 `GitHub 에서 옮기기` → Commit changes.
- 그 항목 아래의 소주제와 글도 함께 따라갑니다. 접힌 항목 위에 잠시 머물면 펼쳐져서 그 아래 항목에도 놓을 수 있습니다.
- 다른 Section 아래로도 옮길 수 있습니다. 자기 자신의 아래 항목으로는 옮길 수 없고, 옮겨 갈 곳에 같은 이름의 항목이 있으면 이름을 먼저 바꿔야 합니다.
- Section 자체는 다른 항목 아래로 옮길 수 없고, 소주제를 Section 으로 올릴 수도 없습니다. 새 Section 을 만들고 소주제나 글을 그 아래로 옮기면 됩니다.
- 항목을 나누려면: 새 항목을 만들고, 나눌 글이나 소주제를 그리로 끌어 옮깁니다.
- **보이는 자리만 바뀝니다.** 폴더와 글 주소는 그대로입니다. 옮긴 기록은 `_data/itemmoves/` 에 쌓이고(`from`, `to` 모두 원래 폴더 경로), 같은 항목은 나중 기록이 이깁니다.
- 옮긴 항목에 새로 쓰는 글은 그 항목의 원래 폴더에 저장됩니다. 브라우저의 `이 항목에 글 쓰기` 는 알아서 맞는 폴더로 갑니다.

## 글 옮기기

| 어디서 | 방법 |
|---|---|
| 브라우저, PC (쓰기를 켠 상태) | 요약 목록의 글을 왼쪽 나무의 항목으로 끌어다 놓기 → 확인 줄의 `GitHub 에서 옮기기` → Commit changes |
| 브라우저, 휴대폰 (쓰기를 켠 상태) | 글을 열어 `이 글 옮기기` → 항목 고르기 → `GitHub 에서 옮기기` → Commit changes |
| 터미널 | `./move-post.sh "기술/예시 주제/sf88wn.md" 수필` (앞은 글 파일, 뒤는 옮길 항목의 폴더 경로) |

- 끌고 가다 접힌 항목 위에 잠시 머물면 펼쳐져서 그 아래 항목에 놓을 수 있습니다.
- **놓인 자리만 바뀝니다.** 글 파일과 글 주소는 그대로라서 이미 퍼진 링크가 끊기지 않습니다. 대신 파일은 원래 폴더에 남습니다.
- 옮긴 기록은 `_data/moves/` 에 파일로 쌓이고(`post`, `to` 두 줄), 같은 글은 나중 기록이 이깁니다. 원래 자리로 돌리려면 그 글의 기록 파일을 지웁니다.
- 파일까지 옮기려면 터미널에서 `git mv` 로 파일을 옮깁니다. 파일 이름이 그대로면 글 주소와 댓글은 그대로입니다.
